# Dealer's Choice Poker Game Website

## Editting Guidelines

- Use Windows Powershell cmdlets and features, as Unix-based commands are not available.

## Project Overview

- The ultimate goal of this site is to host interactive online poker, pinochle, and possibly other card games that allows players to gamble and place wagers.
- Site will have comprehensive user account features, including stat tracking.
- Games are created entirely with React and NextJS, utilizing Socket.IO for WebSockets-based server communications and packages like framer-motion for animating visual effects.
- Authentication is handled via NextJS Contexts, and sesion management utilizes JSON WebTokens with Jose.
- Form validation uses Zod
- Databasing makes use of MongoDB and utilizes Mongoose for Schema validation

## Project Structure

- `'/docs'`: Documentation of features, functions, classes, and other concepts goes here
- `'/misc'`: Location for unused and archived files that should not be considered or analyzed
- `'/public'`: Base folder for all assets
  - `'/public/assets'`: Visual assets suh as card backs, chips, tokens, etc.
    - `'/public/assets/sounds'`: Audio assets
    - `'/public/assets/cards_XX'`: Card face art assets, where XX indicates localization language (e.g. 'en' for English, 'ru' for Russian)
  - `'/public/fonts'`: Font files
  - `'/public/logos'`: Third party logos, such as Discord or GitHub
  - `'/public/uploads'`: Any user-uploaded content is placed here
    - `'/public/uploads/avatars'`: Location for user-uploaded profile avatars
- `'/src'`: Base folder of all source code files that Codex should analyze
  - `'/src/socket.ts'`: Logic handling socket.io events for gameplay on backend websockets server is located here
  - `'/src/server.ts'`: Code for instantiating backend websockets server located here.
  - `'/src/app'`: Location of all site routes and pages
    - `'/src/app/api'`: All API endpoint routes are located here
    - `'/src/app/dashboard'`: Landing page after users log in, contains all subroutes for managing profile settings, viewing statistics, purchasing chips, cashing out, and account management.
    - `'/src/app/forgot-password'`: Location for resetting passwords
    - `'/src/app/game'`: Base route for accessing game features, this is the lobby page for finding and creating games
      - `'/src/app/game/editor'`: Route for creating custom poker game types (under active development)
      - `'/src/app/game/pinochle/\[gameId\]'`: Dynamic route for Pinochle game lobbies that have been created and are being played
      - `'/src/app/game/poker/\[gameId\]'`: Dynamic route for Poker game lobbies that have been created and are being played
    - `'/src/app/help'`: Route for gameplay guides and rule sets for learning how to play Poker or Pinochle
    - `'/src/app/login'`: Route for accessing dedicated user login portal
    - `'/src/app/logout'`: Route for causing user logout process.
    - `'/src/app/register'`: Route for creating a new user account
    - `'/src/app/reset-password'`: Route for resetting a user password
  - `'/src/components'`: Location for storing various page components used across the site
  - `'/src/contexts'`: Location for storing site contexts (such as auth context)
  - `'/src/game'`: Location of game logic code, including and functions
  - `'/src/hooks'`: React Hooks used for various site features
  - `'/src/lib'`: Code for back-end or other features, including databasing, validation, session authentication, emailing, and more
  - `'/src/types'`: Location for storing types declaration files

## Project Coding Conventions

### General Coding Conventions

- Use TypeScript for all new code generated
- Codex should follow the existing code styles found in each file
- Variables and functions should be given meaningful names that are as concise as possible
- Add comments for complex logic and component purposes
- Functions and methods should be given JSDoc-style documentation, including at least a description of the function, parameters, return type, and usage example, with other features included as required

### Naming and Casing Conventions

- Codex must follow PascalCase naming for all TypeScript functions and component names
- Codex must follow camelCase naming for all TypeScript variable names
- Codex must follow lower_snake_case for all fields/properties in databases
- Codex must follow UPPER_SNAKE_CASE for all constants values and environment variables.

### React Components Guidelines

- Codex should use functional components with hooks as found in the project files, and incorporate new ones as required
- Components generated by Codex should be kept small and focused
- Proper prop typing in all component code

### CSS/Styling Standards for OpenAI Codex

- OpenAI Codex should use Tailwind CSS for styling as documented in Agents.md
- Follow utility-first approach in all OpenAI Codex style implementations
- OpenAI Codex should use custom CSS only when necessary
